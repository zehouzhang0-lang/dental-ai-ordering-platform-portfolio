# AI 辅助牙科下单与生产协同平台：老师审阅说明

## 一句话定位

这是一个面向牙科诊所与义齿加工厂的四角色业务协同平台：医生提交病例与修复订单后，订单依次经过客服审核、生产审核、设计确认、工艺执行、质检返工、账单物流和医生收货确认，形成可追踪的业务闭环。

“AI 辅助”在本项目中有两层含义：开发过程中使用 AI 工具协助实现和测试；产品源码中也包含受治理的 AI 助手网关。当前证据不支持把它描述成自主 Agent、RAG 系统或已经在生产环境稳定使用真实大模型的产品。

## 个人职责

据项目所有者说明，本项目由一名人类开发者独立推进。本人负责：

- 将客户和业务方反馈整理为需求、流程、一期范围与验收条件；
- 前端、后端、数据库迁移、对象存储、权限和部署配置的实现与整合；
- 四角色测试设计、测试数据准备、缺陷记录、回归和版本判断；
- 演示、交付材料、版本坐标和证据索引的整理；
- 最终的内部验收、发布与交付决策。

协作记录中的 PM、开发和测试账号，是同一人为了模拟团队视角和验证角色流程而使用的身份；客户与业务方提供需求和反馈，但不等于存在多名研发人员。AI 工具承担代码、脚本、文档和自动化测试辅助，业务判断和最终责任由本人承担。

## 已实现范围

- 医生端：患者与病例组、动态表单、附件、订单提交、进度、设计确认与收货；
- 客服端：资料初审、客户管理、沟通、账单与物流记录；
- 管理端：生产审核、RBAC、数据权限、产品与流程配置、经营管理；
- 生产端：工序 DAG、接单与转派、工时、质检、返工和异常处理；
- 平台能力：MySQL、Redis、MinIO、Flyway、OpenAPI、Docker Compose；
- AI 网关：模型适配、确定性降级、审计、预算/速率控制、重试与熔断、输出保护。

## 当前边界与不足

- 自动化测试与部署探针不等于完整客户验收；历史手工测试结论必须绑定当时的提交、环境和证据；
- 普通附件采用软删除：删除后不再签发新访问地址，但对象不会立即物理删除，旧签名地址可能在到期前有效；
- 对象存储内外地址已在代码中分离，但目标环境仍需重新完成真实浏览器上传、预览和下载验收；
- 账单与物流是内部业务记录，不是支付网关或物流商 API 集成；
- AI 默认走确定性降级路径，真实模型的生产启用与输出质量没有由本归档证明；
- 前端入口和部分后端服务体积较大，模块边界、拆包和可维护性仍可继续改进。
